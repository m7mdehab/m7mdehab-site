# Information Architecture — Working Production Structure

## Primary site goal
Build a durable professional web identity and opportunity-acquisition system for Mohammed Ehab ElNomany that increases visibility, awareness, approachability, online authority, search discoverability and AI-search understanding while converting relevant visitors into role, project, consulting and collaboration conversations.

1. Hero / identity
2. Positioning / professional proposition (may be integrated into hero)
3. Selected work / flagship projects
4. Capabilities / what I solve
5. Skills & technology stack
6. Professional experience
7. Certifications
8. Education
9. Additional experience / teaching / mentoring
10. About / how I think and work
11. Services / ways to work together
12. Writing / evidence-backed insights preview
13. Opportunity / contact CTA
14. Footer / entity links

## Writing / authority system
Writing is now a substantive route family rather than a title inventory.

English:
- `/writing`
- `/writing/[slug]`

Arabic:
- `/ar/writing`
- `/ar/writing/[slug]`

The first editorial set is derived from inspectable project evidence in Presaira, Oil Spill Detection and OpportunityOS. Articles may interpret and generalize lessons from the work, but they do not create new project facts or widen publication rights. Each article links back to the relevant case study and its first-hand evidence trail. English/Arabic pairs self-canonicalize and expose reciprocal language alternates.

A writing route is justified only by a substantive body. Do not create empty categories, thin keyword pages or placeholder article URLs.

## Skills / technology-stack module
The stack must not be a generic logo wall. It should be grouped by meaningful capability families and remain driven by structured data.

Candidate groups:
- Data Engineering & Migration
- Analytics & BI
- Data Science & Machine Learning
- AI Engineering
- Product & Software
- Infrastructure / Delivery / Tooling

Visual direction: compact, tactile and interactive; motion should help scanning and discovery rather than create spectacle.

## Supporting routes
Current substantive route families:
- `/work/[project]`

- `/ar` and localized project/writing equivalents

Create these only when future substance justifies them:
- `/services`
- `/about`

## Conversion path
Selected work → demonstrated capability → relevant service / role fit → opportunity CTA.

Authority path:
Project evidence → first-hand technical insight → case-study proof → relevant capability / opportunity.

Primary CTA language remains: "Discuss a role or project opportunity."
