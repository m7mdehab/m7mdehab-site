# Phase E — Selected Work Rebuild

**Status:** ACTIVE / RENDERED ACCEPTANCE PENDING  
**Program:** Frontend Rebuild — Visual Identity & Homepage Architecture  
**Date:** 2026-09-12

## Purpose

Phase E replaces the legacy six-card homepage project wall with the accepted **Spatial Evidence** role from Phase C: three deliberately weighted entrances into the work, followed by a compact route for the complete project directory.

The work chapter must be the strongest visual proof area on Home without becoming the majority of homepage length.

## Homepage flagship set

Implementation set:

1. **Presaira** — probabilistic forecasting / evaluation / reproducibility.
2. **OpportunityOS** — governed AI / provenance / system authority.
3. **Ghareeb Oglu Commerce** — product ownership / software architecture / ecommerce execution.

### Why Ghareeb Oglu occupies the third slot

Oil Spill Detection remains one of the strongest individual evidence artifacts and is still public and prominent in the site system. It already contributes real Sentinel-1 SAR evidence to the Phase D hero atlas. Using Ghareeb Oglu in the third homepage slot broadens the story from forecasting + governed AI into commercial product/software delivery and prevents the homepage proof layer from becoming visually or narratively dominated by ML/technical research work.

This does **not** demote Oil Spill Detection as evidence. It remains a full case study in `/work`, appears in the system hero, and remains available to writing/discoverability surfaces.

## Browsing mechanic

Production mechanic: **asymmetric spatial gallery**.

Why:

- Phase C already compared materially different project-browsing directions, so Phase E does not need to re-run that decision from zero.
- Spatial Evidence was explicitly assigned ownership of heterogeneous Selected Work composition.
- It allows one project to carry larger inspectable evidence while two contrasting projects remain immediately visible.
- It avoids a six-card wall, carousel-hidden content, artificial scroll hijacking and one-project-per-screen staging.

## Homepage copy contract

Each selected item may communicate only what earns homepage attention:

- project category;
- concise project statement;
- inspectable or public-safe evidence treatment;
- evidence-domain summary;
- direct route into the full case study.

The homepage does not repeat full case-study narrative, detailed technology stacks or service sales copy.

## Complete work directory

New routes:

- `/work`
- `/ar/work`

The directory exposes all six projects in a compact evidence-index treatment. Individual case studies now return to the directory rather than forcing visitors back into the homepage anchor.

The Arabic directory is structural parity only. Its language remains subject to the planned Phase K Arabic editorial/art-direction pass.

## Discoverability contract

Phase E adds the bilingual work-directory routes to:

- canonical metadata;
- reciprocal language alternates;
- sitemap;
- `llms.txt` navigation surface.

Project JSON and case-study canonical URLs remain unchanged.

## Regression rules

Phase E fails if:

- six giant project cards return to English Home;
- the selected set exceeds three flagship entries;
- project evidence becomes decorative or fabricated;
- protected Ghareeb Oglu imagery is redistributed without rights;
- `/work` becomes another long six-card homepage clone;
- mobile requires horizontal scrolling;
- project links or case-study canonicals regress;
- Arabic route parity breaks the existing localization contract.

## Rendered acceptance gate
