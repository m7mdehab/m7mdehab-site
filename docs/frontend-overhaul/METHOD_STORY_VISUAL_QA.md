# Method Story — Render Review Rubric

Use this after integration. Review screenshots in this order: 1440 → 390 → 1920 → 1024.

## 1440×1000 — primary composition

Pass only if:
- headline is the first visual anchor;
- “reliable systems” emphasis is noticeable but not neon;
- support copy reads as secondary;
- stage sequence is immediately left-to-right;
- input side is visibly irregular;
- expose stage looks like information becoming inspectable;
- reduce stage visibly converges;
- build stage visibly assembles;
- output side is visibly calmer and more resolved;
- outputs have more alignment than inputs;
- connector lines support the story without becoming a network diagram;
- CTA is visible but does not compete with the story.

Immediate rejection:
- looks like five cards;
- looks like a dashboard;
- looks like a flowchart from presentation software;
- large glowing glass panels;
- muddy green with insufficient text separation;
- more than one strong accent color;
- icons appear to come from different systems.

## 390×844 — mobile

Pass only if:
- headline does not dominate more than necessary;
- support copy remains short and legible;
- vertical spine clearly communicates progression;
- each stage is visually distinct without requiring interaction;
- no tabs;
- no tiny diagrams;
- input fragments remain readable;
- evidence stack reads at phone size;
- decision convergence does not collapse into visual noise;
- system stack is recognizable;
- all five outputs remain readable;
- no horizontal overflow.

## 1920×1080 — large desktop

Pass only if:
- composition still feels compact;
- shell width prevents excessive stretching;
- connector paths remain attached to their intended regions;
- output rows do not look detached from build;
- no dead horizontal voids appear between stages.

## 1024×768 — tablet

Pass only if:
- responsive reflow is intentional;
- input, transformation, and outcome zones remain distinguishable;
- no stage copy overlaps a visual;
- no connector SVG from desktop remains visibly misaligned;
- the section does not become excessively tall.

## Motion review

Watch once at normal speed without using DevTools.

Pass only if the viewer can verbally describe:
“messy → visible → decided → built → reliable.”

Timing should feel:
- deliberate;
- short-travel;
- soft acceleration/deceleration;
- no waiting;
- no perpetual ambient activity.

Reject:
- looping tracer;
- card bobbing;
- random particles;
- pulsing every output;
- animation that restarts on tiny scroll changes;
- long pinned sequence.

## Typography review

- headline weight: confident, not poster-heavy;
- body copy: at least secondary contrast, never washed out;
- stage title > stage detail > tiny label;
- no serif-stage mismatch;
- no all-caps body text;
- line lengths remain controlled.

## Final “3-second” test

Hide or ignore all body descriptions and look only at:
- headline;
- shapes;
- path direction;
- stage titles.

If “messy reality becomes reliable outcomes” is not obvious within roughly three seconds, do not compensate with more copy. Fix the visual transformation.
